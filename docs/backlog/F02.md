# F02 — Xác thực JWT tại STOMP CONNECT

## Mô tả

Chấp nhận HTTP WebSocket Upgrade sau khi kiểm tra Origin; xác thực JWT tại STOMP CONNECT trước mọi SEND/SUBSCRIBE. Một Spring Boot instance phục vụ tất cả client.

**Chức năng:** F02 · **Key points:** KP4 · **Ưu tiên:** MUST
**Phụ trách chính:** Vòng Kỷ Phong - 52400225 (Backend)
**Phối hợp:** TV1 phần FE; TV2 phần BE/infra; TV3 Lab/Admin và điều phối test.
**Milestone:** W02 - Tuần 2 · **Phụ thuộc:** F01.
**Mốc bắt buộc:** đạt nghiệm thu chậm nhất 24/11/2026.

## Checklist công việc con

- [ ] **FE:** Gửi Authorization: Bearer JWT trong STOMP CONNECT; hiển thị trạng thái xác thực; refresh một lần khi unauthorized rồi nối lại bằng token mới. Giới hạn reconnect khi lỗi.
- [x] **BE:** JWT tại STOMP CONNECT, Origin, cap 5/user, timeout 5 giây, expiry/logout close; whitelist mở rộng có kiểm tra quyền cho F03–F15.
- [ ] **Test:** Token thiếu/sai/hết hạn, Origin lạ, user bị ban, socket thứ 6; không tạo vòng lặp refresh/reconnect.
- [ ] **Docs:** Viết nội dung F02/KP4 bằng tiếng Anh theo văn phong học thuật; cập nhật README/cách chạy/cách test; lưu ảnh, log và số liệu thực tế cho báo cáo/demo.

## Tiêu chí nghiệm thu

- [ ] Socket trái phép bị từ chối; token hết hạn khiến kết nối bị ngắt và client chỉ reconnect với token hợp lệ.
- [ ] Mọi event dùng `{ type, payload, ts }`; client event cần xác nhận dùng application ack có correlationId (STOMP RECEIPT chỉ xác nhận frame); mã lỗi theo contract: `unauthorized`, `rate_limited`, `invalid_payload`, `forbidden`.
